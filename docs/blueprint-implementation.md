# 聚友通信城智能化蓝图落地矩阵

依据：用户提供的[系统功能总纲与智能化蓝图_20261007](https://www.coze.cn/s/jv3i2ggBdlQ/)，2026-10-07 逐项核对本项目。分享页中的“已上线”等标签是原文自述，下表以当前系统代码和验收为准。

## 主账口径
正式启用后，以飞书进销存背后的 ERP 数据库为唯一库存与交易主账；飞书多维表格负责录入/查询镜像，管家婆作为历史数据迁移和核对来源。正式期初必须在全库盘点和往来对账后建立。测试批次不得混入正式报表。

## 角色与权限
| 角色 | 负责 | 不得独立完成 |
|---|---|---|
| 数字大脑 | 全系统健康、账货钱一致性、异常预警、任务协调、老板驾驶舱、备份与恢复核验 | 收付款确认、红冲、删除、权限、工资、正式期初 |
| 数字营业员 | 店员内部副驾：语音填单草稿、商品串码识别、推荐、缺项提醒、价格与毛利测算 | 未经确认直接入账、越权让价、代替实物验收 |
| 业务助手机器人 | 顾客接待：问需求、答已核准的产品/资费、预约或转人工 | 读取成本、工资、其他顾客信息，编造套餐价格或承诺 |
| ERP 规则引擎 | 串码唯一、库存原子扣减、单据编号、审计、复核、对账、账务过账 | 根据模型自由文本跳过校验 |

## 账务命名
- “扎账”统一显示为“交班结算”；全天汇总为“营业日结”。
- “核对钱”区分“资金对账”（系统与实收比对）、“收款复核”（负责人确认）、“往来核销”（应收/应付与收付款配对）。
- “供货商/客户”统一归入“往来单位”，具体角色保持可区分。
- “库存主账”与“飞书查询镜像”保持区分；镜像不能直接修改余额。

## AI 实施顺序
1. 建立受控查询工具：库存、串码、原单、往来、日报；全部按飞书登录身份过滤。
2. 扣子生成结构化单据草稿，规则引擎校验，营业员确认；对话和字段修改留痕。
3. 启用分级复核与飞书通知；不阻断柜台开单，待复核资金不计入已到账余额。
4. 数字大脑扩展为异常解释、采购建议和每日自检；生成建议而不执行财务高风险动作。
5. 顾客接待机器人只用核准知识库，无法确定的价格/资费转人工。
6. 待数据、权限和恢复演练稳定后，再评估视频安防与多店复制。
