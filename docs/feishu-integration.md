# 飞书接入第一阶段：库存查询

## 当前可运行状态

本机演示服务已配置：在项目根目录双击 `start-demo.cmd`，然后访问 http://127.0.0.1:3100/demo 。浏览器页面使用独立测试账套，可登录、查看库存、试开单和查看销售单。后端仍是原项目的 SQLite 进销存逻辑。飞书测试表地址是 https://lcnqk469hw97.feishu.cn/base/VaIqbl84uasGIhsC56Mcn1rmnBb?table=tblKCyoERJgjNPGD&view=vewDOgt3T8 。

本机服务启动时及库存相关业务提交后会尝试把库存单向同步到飞书。飞书连接失败不会把已成功的销售单改成失败，需查看服务窗口中的同步日志并重新启动补同步。飞书表不能直接办理销售或收货。没有云服务器与正式飞书身份认证，手机暂不能打开本机工作台。

测试版可先运行 `node scripts/prepare-demo.js` 创建独立测试账套，再运行 `node scripts/feishu-inventory.js` 导出示例库存。测试账套有 8 个商品、7 个有库存的商品，所有编号都以 `DEMO-` 开头。脚本遇到已有账套会拒绝覆盖。

此版本将原系统 SQLite 中的当前库存单向同步到飞书多维表格。飞书表用于员工查询，不能在表中直接开单、收货或改库存。原系统仍负责销售、采购、退货、串码、成本、供应商和工资的事务校验。

## 现在可以做的事

1. 在飞书创建一个多维表格，名称可用「门店库存查询」。建一张表「当前库存」，第一列设为文本，字段名为「库存键」。
2. 依次创建文本字段「商品编号」「商品名称」「分类」「规格型号」「仓库」「同步时间」，数字字段「库存数量」「预设售价」。字段名要完全一致。
3. 在飞书开放平台创建企业自建应用，启用多维表格读写权限；发布并在企业内启用，然后将应用添加为这张多维表格的协作者。具体权限名称以当前开放平台页面为准。
4. 从开放平台复制 App ID 和 App Secret，从多维表格链接或开放平台工具取得 app_token 和 table_id。仅把密钥保存于本机或服务器的 `server/.env`，不要发到聊天或写入代码。

`server/.env` 添加：

```dotenv
FEISHU_APP_ID=cli_xxx
FEISHU_APP_SECRET=xxx
FEISHU_BASE_APP_TOKEN=xxx
FEISHU_BASE_TABLE_ID=xxx
```

已有真实 `server/data/store.sqlite` 的机器上运行 `npm run feishu:export`，会先生成 `feishu-inventory.csv` 供检查。确认字段和数量后运行 `npm run feishu:sync`。同步以「库存键」识别记录：新增或更新现有库存，不会删除飞书旧行；返回的 `stale` 数量需要人工复核。建议先在测试表验证，再接正式表。未配置飞书密钥时，导出 CSV 仍可用。

## 当前边界

- 原仓库没有随代码提供真实业务数据库。本项目添加的 `server/data/store.json` 和 SQLite 均为虚构测试数据，不能当作真实门店账套。
- 尚未建立飞书登录与原系统员工身份的绑定，也没有可供手机访问的服务器。因此目前不能在飞书中安全地进行开单、收货、退款和结款。
- 本表不传成本、IMEI、供应商余额或工资；如需按角色查询这些数据，应由后端鉴权后单独提供。
- 未启用定时任务。首次试运行应手动同步；部署后再安排定时同步和失败告警。同步期间的表格数据可能比原系统稍旧。

## 下一阶段

取得一份经过脱敏的测试账套后，完善销售/采购等操作界面与端到端验证；随后选云服务器、域名和 HTTPS，将飞书身份与原系统用户一对一绑定，再开放写操作。扣子可在权限模型稳定后接只读查询，不直接执行财务或库存写入。
