# 聚友通信城订货、验收与资金闭环（2026-10-07）

## 口径

本文件是本店系统的业务与内部控制设计，正式会计科目和税务处理须结合营业主体性质由负责记账的人确认。系统只纳入**与本店业务有关**的个人账户流水片段，不要求接入老板或采购经手人的全部个人账单。若不录入外部支付凭证、实际金额和期初门店款余额，系统无法保证资金“分厘不差”。

## 一、订货工单状态与数量

主订货单由营业员创建，指定供应商、商品、数量、约定单价、收货责任人、预计到货日与备注。创建时生成不可改编号，并给老板形成“待付款决策”待办，显示预计金额和已有供应商预付款。

**付款状态独立于收货状态**：未付／部分付／已付／超付待核。支付不能自动把货算进库存。老板确认付款，采购经手人登记实际付款账户、金额、支付时间、外部流水号、凭证和经办人；老板确认是否属于店铺款，不能只按内部转账推定已付供应商。

**物流状态**：待发货 → 已发货/部分发货 → 部分验收 → 全部验收入库；供应商未发或途中货品只显示在途/待到，不计可售库存。每次发货可录供应商发货单号、物流单号、数量；可以多次发货。

**验收事件**：被指派营业员打开自己的工单，逐商品录本次实收、拒收、破损、串码或二维码、实际进价、仓库、验货照片/送货单。原订数量 = 累计合格入库 + 拒收/短缺待处理 + 未到数量。只有本次合格数量入库；重复串码、超过剩余待收数量、错误供应商或仓库一律拒绝提交。每次验收生成独立入库单，记验收人、时间、原单、发货批次、成本来源和证据。

**完成条件**：所有行的累计合格入库数量等于订货数量，且拒收/短缺均已处理，才显示“已完成”。若供应商不再补货，只能走老板批准的“终止未履行部分”，状态为“已终止”，不能伪装成“已完成”。未到货始终留待办，并可设置超期提醒。收货完成后还需看供货商应付/预付是否对清；“货到齐”和“款结清”是两个勾，不混为一个状态。

## 二、门店收付款与现金交接

**按老板澄清后的边界**：系统不追踪老板夫妻之间的私人转账、个人账户全部余额或日常花钱。只记录门店业务本身的销售收款、供应商付款、经营费用，以及营业员把现金交给谁、对方是否实际收到。这里的主要风险是营业员误点“已交”或漏交，而不是夫妻之间的用款。

- 顾客扫码付款到老板账户：销售单记录收款方式、金额与支付平台流水；后续用平台账单逐笔核对是否到账。老板本人账户里的非门店交易不进入系统。
- 收银台现金交给采购经手人或老板：营业员提交“待接收人确认”的交接单，记金额、时间、交出人、指定接收人。**交出人提交不等于接收人收到**；接收人必须用本人飞书账号实点并确认。没收到或金额不符则驳回、写实点金额与原因，原单留痕。
- 收银台现金由老板存入银行卡：营业员先提交现金缴存交接单；老板核对实际银行卡入账金额与流水号后确认。未见到银行入账时保持待确认。
- 老板转款给采购经手人及双方自由使用的个人款：不要求逐笔登记。如果某笔钱实际用于支付供应商，**供应商付款**仍需单独关联订货/进货单、实际金额、外部付款流水和经办人；仅有夫妻间转账不能当作已付供应商。
- 供应商多付、少付、退款与未到货：继续在供应商预付、应付和待退款中反映，不因现金交接完成而自动改变。

现金交接只改变“是否已被指定的人确认收到”的证据状态，**不重复生成销售收入或经营费用**。扎账时，已确认交接从柜台应点现金中扣除；待确认交接显示待办，不能静默锁账。系统可以核实门店交接和已录入业务；若没有平台/银行外部对账单，就不能宣称实际到账已全部核准。

例：营业员说已交现金 500 元给采购经手人，系统只生成“待接收人确认”。她在自己的飞书账号实点 500 元并确认后，该单才显示“已确认收到”；若她没收到，则驳回并留原记录。老板和采购经手人之后怎样用自己的钱，不属于这张交接单。

## 三、利润、现金与待收分开看

经营看板至少分三块：

1. **经营成果**：已完成销售收入 − 对应已售商品成本 − 已确认经营费用 ± 售后/成本调整。采购未卖出的库存仍是库存价值；转账不是利润变化。
2. **资金实流**：顾客到账、平台手续费、供应商付款、费用、已确认/待确认现金交接与支付渠道未匹配流水；按外部账单逐笔核对。
3. **未来应收与在途**：移动业务分月预计、移动公司已确认、实际到账；国补申请/核销/应收/到账；供应商预付、待到货和退货应退款。预计酬金不能混作当天已收现金。

不以“收入减进货付款”代替利润，也不把移动酬金预计额或国补在途额当作实收。日报显示未匹配金额和最老未结天数，不允许靠一个总余额掩盖差异。

## 四、角色、留痕与防漏

| 环节 | 操作人 | 复核/限制 |
|---|---|---|
| 建订货 | 有采购权限的营业员 | 自动推送老板付款待办，保留原始数量和改版记录。 |
| 付款决策 | 老板 | 同意金额、资金来源和用途；拒绝或部分批准须说明。 |
| 实际对外付款 | 采购经手人或授权财务人员 | 外部流水号不可重复；上传凭证；不得自动生成收货。 |
| 发货登记 | 指派营业员或老板 | 供应商发货单/物流证据。 |
| 到货验收 | 当前指派营业员；必要时交接指派 | 逐项点数与扫码；高值手机建议另一人复点；不同人操作都追加事件。 |
| 差异处理 | 营业员提出，老板裁决 | 短少、破损、价格不符、串码重复只走异常单；不能强行计入合格库存。 |
| 日结 | 营业员实点，另一人复核，老板签认 | 对照外部支付、柜台现金、待确认交接、供应商往来、在途与库存。 |

工单只追加事件：建单、审批、付款、发货、每批验货、入库、差异、供应商退款、转派、完成/终止；事件记录操作者飞书 ID、时间、前后值和证据引用。更正用补正/冲销事件，禁止静默删除原记录。通知未送达要重试并在待办里显红，不影响原单的已提交状态。

## 五、当前系统核对

已存在：订货单、分批入库、数量上限、串码重复阻断、订货预付款、供货商往来余额和操作日志；数量全部收到后状态变为 `received`。现有正式收货会直接创建采购入库单并增加可售库存。

现已补上：订货通知老板、付款决策待办与批准总额限制、默认验货人及老板转派、每批入库事件、老板才可终止余货、现金交接本人确认。老板批准或暂缓均留事件；实际付款须另行登记，未批准或累计超过批准额的订货关联付款会被拒绝。仍缺：发货批次、独立验货草稿和附件、未到货超期、平台/银行流水逐笔对账。现金交接只证明双方确认，不能代替外部到账核验。

## 六、优先实施与验收

1. 在测试账套先增加付款待办与指派、收货证据/发货批次、到货异常；保留原入库事务，验收通过才入库。
2. 完善现金交接待办与收款凭证；只导入/手录**门店相关**的平台和供应商付款流水，不采集夫妻私人交易。
3. 将供应商预付、分批收货、退款与库存、往来和日结连通，按订单显示：订量/发量/实收/拒收/欠货/已付/预付余额/应付余额。
4. 加入移动酬金和国补在途的逐期对账，不计入已收资金；老板首页显示超期与差异。
5. 用模拟案例验收：分三批到货、少货、串码重复、付多款、现金已交未收、现金金额不符、多次付款、供应商退款、跨日收货、弱网重复提交。每个案例核对库存、应付/预付、门店款、利润、员工事件与通知。

正式使用前，需用真实支付流水和盘点数据核定期初门店款、库存与供应商往来；没有这些期初，系统无法给出可靠的累计利润和资金余额。
