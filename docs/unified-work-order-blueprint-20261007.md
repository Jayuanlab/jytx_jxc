# 聚友通信城：统一工单与智能办公蓝图（2026-10-07）

## 目标与现状

本店老板主要做监督、核定和查账；员工负责接待、实物操作与确认。所有业务要从开始到结束有一条可追溯的工单链。系统应先减轻填写负担，再保证库存、资金、往来、工资口径一致。

现有接待单、学习单、协助单、销售单、移动业务单、国补单、供应商往来、交班单、扎账单和审计日志已经分别存在；目前**没有统一的工单编号和强制关联**，销售等业务可以不经过接待单，数字大脑仍是规则巡检，尚未接入大模型。当前为测试账套，不能把测试库存、收入和员工报酬当成正式账。

## 一条业务链

1. **开工单**：到店、电话、微信、外出拓展、售后或店内任务都能建单；扫描客户手机号后先提示历史档案、未结工单和回访。没有客户的学习/内部任务也能建单，不伪造客户。
2. **记录过程**：可追加需求、报价、推荐、协助、照片、凭证和回访；每次追加都记员工、时间、来源，历史内容不能静默覆盖。AI 可以生成摘要和待办草稿。
3. **转业务**：从原工单派生销售、维修、移动业务、国补、订货或退货子单；同一客户可有多次接待，同一次接待可关联多张交易，避免手机号直接充当单据唯一键。
4. **履行与收付**：串码/二维码、仓库、数量、价格、补贴、收款和库存变动在同一个数据库事务内提交；未到账、分期酬金和应收留待后续结算，不假作实收。
5. **复核与结案**：营业员确认实物与收款，另一人复核重要差异，老板裁决协助、转化贡献、积分和提成。结案后仍允许原单关联的退货/更正，必须留反向流水。
6. **扎账与报酬**：按营业日汇总交易、资金、库存、移动BOSS七组和待收款；已审核的贡献才进入工资草稿。交班和正式日结分开。

## 建议的数据骨架

| 对象 | 最少字段 | 必须满足 |
|---|---|---|
| 客户档案 | 内部客户 ID、手机号、同意使用记录、联系方式、历史工单 | 手机号可变更且可重复归属争议；客户 ID 才是系统关联主键。 |
| 主工单 | 连续可读单号、类型、渠道、客户 ID、负责人、当前状态、创建/关闭时间 | 每张业务子单有主工单 ID；补录要标识来源和原因。 |
| 工单事件 | 工单 ID、事件类型、操作人、时间、前后状态、证据引用 | 只追加；修改用新事件与版本号。 |
| 子业务单 | 原单 ID、外部单号、金额/数量、业务日期、履行/收付状态 | 外部单号和幂等键防重；退货指向原单。 |
| 资金流水 | 账户、正负金额、发生/入账日期、外部流水号、来源单 | 现金、微信、支付宝、银行、移动酬金、国补分别核对。 |
| 库存流水 | 仓库、SKU、串码或批次、正负数量、成本来源、业务单 | 现存量由流水和期初推导/核验；串码同一时点仅处于一个状态。 |
| 贡献申请 | 工单 ID、参与人、角色、证据、建议比例、老板裁决 | AI 只能建议；老板确认后形成积分或提成；协助份额从原销售提成扣减。 |

可读单号采用业务前缀 + 营业日 + 当日序号；数据库仍用不可变内部 ID。客户手机号、设备串码、平台流水号不互相替代。

## 数字大脑、数字副驾与机器人边界

- **数字副驾（员工端）**：语音或拍照生成草稿，自动带出商品、库存、客户历史、供货商、资费与回访；提交前醒目显示识别依据、置信度和未填项。员工确认后才写主账。
- **数字大脑（后台）**：持续跑确定性规则，包括负库存、串码重复、收款未匹配、重复单、毛利异常、国补在途超期、移动酬金逾期、待回访、待复核、备份失败。把异常推给正确的人并跟踪到处理完成。
- **老板裁决箱**：只汇总例外和待批准项目，给出原单、证据、差异、影响金额和 AI 建议；一键通过/退回并写原因。普通开单不因老板未读消息而停住，涉及超权限价格或付款的动作按风险规则另行阻断。
- **顾客机器人**：只读取经审核的商品/资费/售后知识，先做咨询和预约；报价、补贴资格、合同承诺和个人资料由员工确认。不能看到成本、工资、其他顾客档案。
- **学习闭环**：AI 根据已结案工单生成知识草稿和培训提示；老板核准后才能进入对客知识库。模型输出永远不是库存、现金或工资的唯一依据。

## 先补的准确性与稳定性保护

1. **测试/正式账套隔离**：正式启用前全库盘点、往来余额核对、员工身份核定；保留测试账供演练。禁止测试单据流入正式报表。
2. **统一交易事务与幂等**：业务单、库存、资金、通知出箱一次提交；双击、弱网重试和飞书回调重放只能形成一单。失败不留半张单。
3. **金额用整数分保存**：销售、成本、提成、国补、酬金和应收统一四舍五入规则。每个报表记录统计口径、截止时间和数据来源；不把“缺资料”显示成 0。
4. **日结/月结锁期**：锁定后禁止回填旧日期；更正以原单关联的补正单进入当前日期。解锁须老板原因和复核记录。当前日结版本的解锁后重关、历史补正仍未形成完整闭环。
5. **对账证据链**：平台实收、移动BOSS、供应商、银行/支付平台流水应保存外部流水号和附件；自动匹配成功、未匹配、金额不同三种状态，差异有责任人和截止时间。
6. **可恢复备份**：每天加密备份数据库及附件到异机，每周在隔离环境实际恢复并核对行数、账面余额与串码数。仅有“备份成功”提示不足以证明可恢复。
7. **角色与隐私**：员工只看所需客户和业务；成本、毛利、工资、身份证明和手机号按角色限制；离职立即停用，重要审批禁止本人复核。对客 AI 只读脱敏知识。
8. **监控与回滚**：服务、数据库、飞书同步和通知发送分别监控；发布前备份，发布后自动健康检查，异常可回滚程序并核对数据迁移。

## 老年友好的使用方式

首页固定六个大入口：**接待/开单、扫码查货、今日待办、交班扎账、综合查询、老板审批**。手机号/串码/订单号放在同一个大搜索框；搜索结果直接显示“客户—接待—交易—收款—售后”的时间线。大字和高对比度为默认，触控区域至少足够手指点击；每页固定返回与退出，长表单自动保存草稿、显示完成进度。可扫条码/二维码、语音说业务，常用字段使用可搜索下拉，发现重复客户或单据时直接给出候选。

## 交付顺序与验收

- **第一阶段：账准且可恢复**。测试/正式隔离、工单关联、统一流水与金额、锁期补正、异机恢复。用并发开单、断网重试、重复串码、跨日退货、退款、支付差异验证。
- **第二阶段：员工省事**。大搜索、扫码、可搜索下拉、草稿、自动回填、移动端大字、交班任务。实测由员工完成一笔销售/一笔移动业务/一笔无成交接待，记录点击数和耗时。
- **第三阶段：AI 辅助**。扣子工作流接入只读查询、语音填单草稿、异常解释、老板待办建议；建立脱敏评测集，测试错误识别、越权问答、重复提交和人工接管。
- **第四阶段：对客与成长**。顾客咨询机器人、回访提醒、知识库、学习单建议、营销线索；老板核准后发布。

上线判定：任取一笔业务能从接待追到库存/资金/结算/报酬；任取一笔资金或串码能反向追到原单；失败重试不重单；日结差异可解释且锁期后不静默改账；异机恢复结果与备份校验一致。
