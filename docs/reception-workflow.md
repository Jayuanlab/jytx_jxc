# 客户接待单与协助单（测试期）
依据：用户提供的[接待单到成交全流程](https://www.coze.cn/s/rTk0LSNWr3A/)和 2026-10-07 口头补充。本文说明当前可运行范围；文档里的“咪咪”自动推荐与 Coze 模型代填尚未接入。

## 账务口径
- 每次接待建一张客户接待单；同一手机号对应一个顾客档案，可有多张接待单。手机号是当前识别键，尚未做短信实号核验；老板结案时须核实，不能仅凭员工填写判为有效。
- 接待单记录来意、来源、需求、推荐、复盘和时间线。未成交须记原因，可设回访时间。成交关联销售单或移动业务单；关联业务单后仍需提交结案并由老板确认。
- 转介和主动协助形成接待单下的协助记录，含发起人、承接人、协助内容和审核结果。老板逐笔核准积分。若关联销售单已有提成，老板可按该单净毛利的 1%–3% 核准协助分成；金额从原销售人提成转给协助人，不能超过原提成可分余额，退货时按比例冲回。
- 加微信由店员申报、老板核验后积分入账。同一手机号只准领一次加微信积分。
- 结案“有效/无效”由老板判定。无效接待的核定积分不低于 50 分；其余接待、协助、加微信积分由老板逐笔输入。积分仅为独立记录，**没有自动折算成工资或现金报酬**。
- 接待、加微信、协助和结案都留操作者与时间。历史业务单不允许重复关联；服务器事务与请求幂等键控制重复提交。

## 尚待规则与外部数据
- 接待页已有规则提醒，可提示补记需求、推荐、回访和待审核事项；协助分成页显示净毛利、可分提成和 1%–3% 计算结果。扣子智能体尚未接通业务工具，因此这些提示是确定性规则，尚非大模型判断；模型文字不会直接记账。
- 回访到期的飞书主动提醒、实名手机号核验、顾客微信关系证明、积分到工资的换算规则、协助报酬比例、跨门店归属规则，需在测试通过及老板提供规则后上线。
- 飞书多维表格当前是查询/录入镜像；新接待流程现运行在飞书网页应用和 ERP 主账。接待单镜像到多维表格需继续配置。

## 学习单
- 所有在职员工可随时提交学习单，类型覆盖接待、销售、移动业务、交班、采购、盘点、售后与培训。完整记录事件、所学和心得，可选关联现有业务单。
- 学习单提交后为待审核，老板逐单决定通过及积分，未通过须说明原因。学习积分单独保存，不自动折算工资或现金。

## 跨次接待的转化贡献
- 甲的早期未成交接待与乙的后续成交接待保留为两张单，并用同一顾客档案关联。甲可从同一手机号的后续销售单下拉选择，提交转化贡献说明。
- 规则引擎给老板列出手机号一致、时间先后、原接待需求/推荐/回访/复盘等证据与缺项；这只是资料完整度判断，不能证明真实沟通贡献。老板最终认可或驳回并核定积分。
- 获认可后在乙的接待单生成有效转化协助记录。老板若决定分提成，再按成交净毛利 1%–3% 从原销售人的既有提成中分给甲，退货冲回。
