# 每日扎账与双人复核：目标及现状（2026-10-07）

依据用户转发的“每日扎账”功能说明，作为本项目**目标要求**记录。转发文字描述的功能不能直接算作本系统已上线；本系统当前实现以 `server/src/closeouts.js`、`server/src/erp.js`、`web/close.js` 为准。

## 当前可运行

- `/close` 由营业员提交交班结算：按本人上次交班之后、截至当前的销售单、退货单和收支流水生成班次快照。
- 自动显示销售笔数/金额、退货笔数/金额、按账户净流水、上次实点现金、本次应点现金；营业员录入实点现金和交接人，差异必须写原因。
- 提交后通知负责人；只有老板可确认或退回，退回后原营业员可补正实点现金并保留修订历史。
- `/api/daily-report` 另有按自然日统计的销售、退货、毛利、收款方式与员工报表；它尚未与交班单合成一张可锁定的完整扎账日报。

## 目标验收：一张日报

| 区块 | 目标内容 | 当前差距 |
|---|---|---|
| 当日交易明细 | 每笔商品/机型、串码、单号、数量、经办人、成本、毛利、收款账户；退货与原单关联。 | 日报只列部分最近订单；交班页只有合计。成本与毛利按权限展示。 |
| 当日汇总 | 销售、退货、净额、成本、毛利、各账户实收，与外部流水核对。 | 合计分散在日报/交班页；尚无外部平台流水勾对。 |
| 手机与配件库存 | 昨日结存＋今日入库－今日销售±退货/调拨/盘点＝今日结存，按仓库与品类。 | 未在扎账页形成完整库存桥接与差异核对。 |
| 贵重品清点 | 可售贵重串码清单、实点结果、差异原因和复核证据。 | 尚无“必点”任务与逐串码清点签署。 |
| 资金账户 | 现金期初、收付、备用金、实点、打款；微信/支付宝/银行卡等系统额与平台额。 | 现有现金应点/实点；备用金、打款及平台实收勾对未接入。 |
| 空充与移动业务 | 平台余额、充值额、分月应收、结算确认及到账差异。 | 移动分月台账已有；平台余额和扎账联动未实现。 |
| 往来单位 | 客户应收、供应商应付/预付及当日变动。 | 供应商往来已有；客户应收、统一日报和账龄未完成。 |

## 目标验收：双人复核和锁期

1. 营业员发起当日扎账，选定交接人，系统生成只读快照；贵重串码实点和现金实点由人填写。
2. **另一名在职营业员**领取复核任务；提交人不能领取或复核自己的单。复核人逐栏确认或驳回，驳回必须填疑义和差异原因。
3. 复核通过后由老板查看异常和签认，再锁定该营业日。锁期后不直接覆盖历史；新发现差异通过下一期的补正/冲销单处理，附原单和审批链。柜台正常开单不因待复核单中断。
4. 老板可按原因解锁某日；记录解锁时间、操作者、原因、影响单据和重新复核过程；页面明确显示“老板已解锁该日期”。
5. 飞书通知提交人、交接复核人和老板，并保留每一步的操作者、时间、表单快照与修改痕迹。

**边界**：当前 `receiverId` 只是交接对象，线上确认接口只允许老板调用；绝不能称为“双营业员复核”。当前 `已确认` 也不锁定销售、库存或自然日。未来锁期不能简单拒绝退货和正常新单，需定义跨日补正与原单引用。

## 移动BOSS人工对账：七组定稿

**保留原七组，不删。** 每组按“我方账自动汇总｜移动BOSS手填｜差异自动计算”展示，手填栏记录抄录人、时间和可选截图；差异不为零时标红并要求说明。移动BOSS无法接口取数，不能把人工录入伪称系统同步。默认七组由老板配置启停和顺序，但已使用的历史模板须保留当时版本。

| 组 | 必须分开的数值 | 我方自动取数条件 |
|---|---|---|
| 1 新开卡／补卡 | 新开卡笔数、补卡笔数分别比较。 | 业务单须有明确子类型、移动外部单号和办理状态；目前仅有泛“号卡”，需补“补卡”类型。 |
| 2 话费充值 | 成功笔数、成功金额分别比较。 | 以移动办理成功时间归日，失败、撤销和重复单不计正向金额。 |
| 3 融合宽带 | 新装笔数；如博士页另含续约/移机，另作子项。 | 业务子类型须区分融合宽带与普通宽带。 |
| 4 套餐变更 | 升档笔数、降档笔数分别比较。 | 需记录原套餐、新套餐、生效日和移动外部单号；当前泛“套餐”不足以自动拆分。 |
| 5 设备绑合约 | 办理成功笔数；有需要时显示绑定设备串码。 | 需新增终端合约子类型，并关联手机销售单或串码。 |
| 6 空中充值 | 期初余额、当日增减、期末余额分别比较。 | 我方须先建空充资金台账；当前无可靠自动余额，不能显示零冒充已核对。 |
| 7 移动业务酬金 | 当日新增预计酬金、移动确认应收、实际到账**分开显示**。 | 预计、确认、到账的业务日期和月份不同；移动BOSS若只显示一种口径，营业员须选择对应口径后才能计算差异。 |

**增加一个异常区，不挤入七组：撤销／退订／扣回／冲正及“我方有单、博士无单”清单。** 这不是第八个简单合计数，而是逐笔核对原单、外部单号和金额的例外事项；不处理完不能判该日移动业务对账通过。

## 准确性与锁期原则

- 先用测试数据复核“售价－原单成本－退货影响＝毛利”；手机台数按串码件数与数量双校验；现金按账户流水、现金实点、备用金、打款分开。用户转述的 -17356/+674 属于另一系统曾出现的错误，不能当作本系统已复现或已修复。
- 临时扎账用于交接抽查，可一日多次；正式营业日结按自然日生成、双人复核和老板签认后锁期。锁期后的合法退货/错账用有原单关系的补正或冲销记录处理，不直接擦改历史；“全程零红冲”不能解释成禁止必要的会计更正。
- 开单与对账独立：待复核或存在差异时，柜台可继续正常办理，异常单留待老板处理；不能把未确认的移动酬金当作实际到账现金。
- 当日锁期、老板解锁及移动BOSS七组均**尚未开发**，按上述口径作为后续实现与验收标准。
