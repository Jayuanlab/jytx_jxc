# 商品编码、仓库与反向操作核对（2026-10-19）

## 已确认的业务规则

1. 商品编码是贯穿商品档案、入库、库存、调拨、销售、退货、供应商往来和报表的主线。一个真实商品只使用一个稳定编码；不能因换仓而另造商品编码或改写历史单据上的编码。
2. 商品分类只描述商品，一级至三级分类均不带仓库。新增分类只需选择父分类并填写名称。
3. 新增商品先校验必填资料，再生成并显示唯一编码；编码生成成功才允许保存。保存商品档案不要求选择仓库，也不创建虚假的零库存仓位。
4. 采购验收入库逐项选择实际入库仓位，库存以“商品编码＋仓库”记录。同一编码可以在多个仓库有库存。调拨只改变仓库库存和位置流水，不新建商品编码，不改变全店总数量和总成本。
5. 历史单据和已锁定日结保持原貌。更正、退回、冲正都关联原单，另写一笔有日期、有操作人、有原因的事件；后续业务读取更正后的净余额。任何反向操作只能执行一次或在允许范围内部分执行，重复提交不能重复影响余额。
6. 编码层级为“商品编码 → 69 码/商品条码 → 单台手机串号”。商品编码是唯一且稳定的档案主键；69 码是该商品的识别资料，不能未经核对就当作唯一主键（现有商品目录出现多个商品编码共用一个 69 码）；串号标识具体实物，串号的在库、已售与所在仓位必须可追溯。

## 目前发现的问题与证据

| 位置 | 现状 | 风险 | 要求 |
| --- | --- | --- | --- |
| 线上“新增分类” | 强制填写“所属仓库” | 相同分类被人为拆到不同仓库 | 去掉仓库字段和服务端仓库校验；已有分类的归属不因迁移改变 |
| 线上“新增商品” | 强制填写“所属仓库”；“配件产品/维修材料”下目前只有“后盖、屏幕总成”，没有“电池” | 建档受仓库限制；输入未建档的“电池”后提交失败 | 分类先建档或由同一事务安全建档；商品建档无仓库；编码生成成功后才保存 |
| 本地 `web/office.js` 与 `server/src/erp.js` | 商品记录含 `warehouseId`，保存商品时建立零库存仓位；采购入库从商品档案取仓位 | 只删表单限制会把货入错仓；同款换仓可能产生另一 SKU | 同步改商品、采购、库存、销售与调拨逻辑 |
| 本地 `server/src/inventory-transfers.js` | 目标仓若无同款，会调用 `saveProduct` 建一个新商品 | 商品编码分叉，历史串码和成本追溯复杂 | 目标仓建立同编码库存位置，不复制商品档案 |
| 线上“移动业务结算”与本地 `carrier-rentals.js` | 可登记、确认、到账；未见撤销或扣回入口 | 误单、结算差异和运营商扣回无法形成闭环 | 增加原单关联的撤销、补充结算、到账冲正、扣回 |

## 新增商品的原子流程

1. 校验名称、一级分类、单位、库存管理方式、售价；需要三级分类“电池”时先确认其已建档。
2. 服务端分配唯一商品编码（例如下一可用 JY 编码），展示给操作人核对。预览编码应有短期保留或保存时在同一事务中重新校验，避免两人同时建档获得同一编号。
3. 保存时以编码为唯一键一次性提交商品；分类引用有效才成功。失败时既不占用商品编码，也不产生商品、仓位、库存流水或审核记录的半成品。
4. 商品编码之后不可直接修改；确需纠错要建立经审核的编码映射，保留原编码在历史单据中的可追溯性。
5. 入库选择仓位后产生首条库存位置；销售、退货、盘点和调拨以原商品编码与具体仓位定位。跨仓查商品时按编码汇总，仓位明细单独展示。
6. 扫 69 码命中多个商品时显示候选商品编码供人工选定；扫串号应定位唯一实物并显示其商品编码和当前仓位。调拨更新串号所在仓位，不换商品编码或串号。

## 全业务反向操作清单

| 原操作 | 正确的反向流程 | 需要同步影响的账与限制 |
| --- | --- | --- |
| 商品/分类误建 | 无业务引用时停用或归档；有引用时保留编码及分类历史，用更正映射 | 不能删除导致旧单找不到商品；仓库调整不改编码 |
| 采购订货、预付款 | 未收货可终止未履约部分；预付款退款单或转用经确认后另记 | 不改已收货、已付款历史；供应商预付余额和资金流水分别核对 |
| 采购入库 | 按原采购明细办采购退货；已售或已耗用的数量不能假装返库，另办供应商价差/索赔 | 库存数量、串码、成本、应付、退款/抵扣分别入账；不能超过可退数量 |
| 供应商付款、退款、抵扣、价保 | 错账用原款冲正或反向抵扣；真实退款用新资金流水；价保差异用补差单 | 原账户原金额核对；应付、预付、可抵扣额不能出现虚假现金 |
| 销售、收款、赠品 | 未完成可撤回申请；已完成按原销售明细退货/换货或红冲，实际退款单独确认 | 库存、串码、顾客应收、原收款账户、国补、赠品和提成须按同一原单联动 |
| 维修、耗材、服务费 | 未执行可撤销；已用耗材不可凭空恢复，按实际返还和退款做关联调整 | 耗材库存、服务收入、员工提成分开处理 |
| 移动业务登记 | 尚未确认结算时可申请作废并保留原业务编号；已确认时不能删除 | 关联接待、销售、预计返费、红包/提成状态要同步标记，不影响其他月份 |
| 移动月度结算确认 | 结算单有差异时追加正负补充结算记录，引用运营商原结算单 | 已确认额＝原确认额＋补差额；不得小于已净到账额；原确认记录不改 |
| 移动返费到账 | 误登记到账时按原到账流水、原账户做冲正；运营商真实扣回时登记负向扣回流水 | 净到账＝到账－冲正－扣回；待到账＝确认额－净到账；避免重复流水号和重复扣回 |
| 现金交班、日结 | 待审核退回补正；已确认/锁定后用下一期更正单并显示前期差异 | 已锁定快照不静默重算；当期余额承接更正；现金账与空冲账分开 |
| 工资、佣金、红包 | 未发放可更正；已发放用下期正负调整并关联原业务 | 不直接修改过去工资单；防止退货或返费扣回导致重复扣减 |
| 库存盘点、调拨 | 盘点差异以复核调整；调拨误操作做新的反向调拨 | 反向调拨按当前实物和成本校验，不能让仓位负库存；全店总量和总成本守恒 |

## 验收用例（独立测试数据）

1. 不选仓库新建“宜鸿OP-A72电池”：先建三级分类“电池”，编码生成后保存；检查唯一编码、无零库存仓位、无采购与资金流水。
2. 同一编码分别入 A 仓 2 件、B 仓 3 件：商品目录只有一条；库存两条；总库存 5 件。调拨 A→B 1 件后两仓为 1、4 件，总成本和总数量不变。
3. 两人同时申请编码：只能生成不同编码，或其中一人收到明确重试提示；不能出现重复编码或半张档案。
4. 同一 69 码关联多个已存在商品编码时，扫码展示候选而不自动并档；一台手机的串号在全店只对应一个在库或已售实物记录，调拨后编码、69 码和串号不变。
5. 采购退货、销售退货、调拨反向操作各执行一次后，再重复提交同一请求：第二次拒绝，数量、成本、往来余额和资金余额不再变动。
6. 移动结算 200 元、到账 120 元、补差 -20 元、运营商扣回 30 元：净确认 180 元，净到账 90 元，待到账 90 元；原结算及银行流水保留；日报只在正确日期计入相应事件。
7. 前一天日结锁定后执行上述更正：原日结数值和哈希不变，当天出现更正事件，后续汇总使用净额且能追到原单。
