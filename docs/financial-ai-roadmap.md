# 聚友通信城：财务与 AI 升级清单

更新：2026-10-07。当前仍为测试期；正式期初以全库盘点和往来对账为准。

## 已有能力
- 飞书登录、商品档案、销售与退货、数量/串码库存、采购及供应商往来、盘点、收支流水和日报。
- 2026-10-07 测试批次：216 种商品、2001 件，其中串码 144 件、配件数量 1857 件；均标记为测试。
- 自动 SQLite 备份已启用；恢复演练和界面化还原尚未完成。

## P0：让账可靠（正式启用前）
1. **测试账与正式账分离**：保留测试批次标记；正式启用时冻结测试单据，盘点后另建正式期初；查询与报表明确选择账套，绝不将测试库存混入正式结余。
2. **单据不可直接改历史**：销售、退货、采购、采购退货、收付款、费用、盘点调整均有唯一编号、原单关联、经办人、审核人、时间、附件、撤销/冲销轨迹。
3. **每日收款对账**：按现金、微信、支付宝、银行卡等账户汇总系统应收，与支付平台/银行实收、现金实点逐笔或按批对账；差异记录原因、责任人及复核。
4. **库账一致校验**：手机串码全局唯一且一件一号；配件按数量；库存流水合计等于余额；负库存禁止；期末盘点有冻结和复核。
5. **一键备份与受控还原**：备份含 SQLite、飞书表结构配置与关键附件清单，校验文件可读；还原前自动再次备份，暂停写入服务，恢复后核对库存、单据、往来与权限；定期异机保存与恢复演练。
6. **权限分离**：店员可拟单，仓管可确认实物，店长/老板审核折扣、退货、盘亏及大额付款；本人不能审核本人高风险单据；飞书账号停用应立即失去权限。

## P1：补齐财务闭环
1. **往来单位主数据**：统一“往来单位”档案，角色分供应商、客户、其他往来；记录主体全称、简称、联系人、电话、结算方式、启用状态，重名合并保留历史映射。收到真实名单后才补缺失项，不编造期初金额。
2. **客户应收**：赊销、收款、退款、预收、核销与账龄；供应商已有四类往来余额沿用并与应付科目对账。
3. **会计凭证/总账**：业务单据自动生成可追溯的凭证草稿；科目至少包含库存商品、商品销售收入、销售成本、现金、银行/支付平台、应收、应付、费用、业主投入等。会计审核后过账，借贷平衡，错账用冲销凭证。
4. **成本核算**：串码商品用实际单件成本，配件确定一种成本方法并固定执行；退货按原单成本回冲，采购费用分摊和成本调整有追溯。
5. **月结与报表**：试算平衡、利润表、资产负债表、现金流及库存/往来明细；月结后锁期，调整进后续期间并注明原因。
6. **发票与原始凭证**：采购票据、销售发票、支付凭证关联业务单；号码查重，保留原文件、哈希与修改记录；税额和科目按实际纳税身份及会计政策配置。

## P2：AI 帮店员办事
1. **语音/文字生成草稿**：员工在飞书说“卖一台华为某型号，串码…，微信收款…”，模型只提取字段、匹配商品、列出缺项和候选项，不直接入账。
2. **确定性校验**：由 ERP 验证串码、库存、价格权限、往来主体、金额和重复提交；高风险差异突出显示；确认后通过正式单据接口原子提交。
3. **AI 查账**：自然语言查询库存、毛利、欠款、日结差异；回答附数据日期、筛选条件和原单链接，成本和工资按角色遮蔽。
4. **票据识别与对账建议**：识别小票/发票/对账单，生成匹配建议；不确定项目交人工确认；模型输出、人工修改和最终凭证均留痕。
5. **异常预警**：重复串码、异常折扣、频繁退货、负毛利、久未收款、供应商余额异常、漏日结、备份失败推送飞书。
6. **模型接入**：优先复用现有扣子/飞书入口；通过受控工具调用后端草稿与查询 API。模型密钥仅保存在服务端，按员工身份和权限调用。

## 验收顺序
- 完成测试数据全流程：手机/配件销售、退货、重复串码、库存一致、日报、往来、权限。
- 导入真实往来单位和营业员名单，验证去重与飞书身份绑定。
- 完成备份还原演练及账套隔离；正式盘点、往来对账后建立正式期初。
- AI 从只读问答和填单草稿上线，连续核对准确率后再扩大自动化范围。
